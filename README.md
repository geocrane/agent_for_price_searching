# search_agent

Инструмент находит рыночные цены на товары из вашего списка и собирает результат в Excel-отчёт
с обоснованием по каждой позиции.

Как это работает: вы загружаете файл с наименованиями → агент ищет источники в Google, открывает
найденные страницы (в том числе через антибот-защиты), извлекает с них цены с помощью языковой
модели, отбрасывает приманки и выбросы, выводит итоговую цену с диапазоном по источникам и
комментарием — что именно за товар нашёлся и насколько ему можно верить.

Работает локально на вашем компьютере с обращением в облако УВА к моделям: интерфейс открывается в браузере.

## Что нужно до начала

| Что | Зачем | Как проверить |
|---|---|---|
| **Python 3.11 или новее** | на нём работает сам инструмент | `python3 --version` (Windows: `python --version`) |
| **git** | скачать проект | `git --version` |
| **Ключ Foundation Models** | языковая модель читает страницы и извлекает цены | см. шаг 1 |
| **Ключ Serper** | поиск источников в Google | см. шаг 1 |
| ~2 ГБ на диске | виртуальное окружение + браузер Chromium | — |

Если Python не установлен: [python.org/downloads](https://www.python.org/downloads/). При установке
на Windows обязательно отметьте галочку **«Add Python to PATH»**.

Всё остальное — виртуальное окружение, библиотеки, браузер для загрузки страниц — скрипт запуска
поставит сам.

## Шаг 1. Получить два ключа

**Ключ модели (`FOUNDATION_KEY`)**

1. Отправить запрос на доступ к Облаку УВА.
2. Откройте присланный после регистрации Excel.
3. Найдите поле  **FOUNDATION_KEY** и скопируйте ключ.

Модель — это то, что читает страницу магазина и понимает, где там цена именно нужного товара,
а где цена аксессуара, доставки или «от 3 штук». Без неё инструмент не работает.

**Ключ поиска (`SERPER_API_KEY`)**

1. Зайдите на [serper.dev](https://serper.dev) и зарегистрируйтесь под любым email. Бесплатно и без телефона регистрируется на outlook.com
2. Скопируйте API-ключ из личного кабинета.

Бесплатно даётся 2500 поисковых запросов — примерно столько же позиций можно обработать. Когда
они кончатся, заведите новый ключ и вставьте его в интерфейсе.

## Шаг 2. Установить

Откройте терминал (macOS: Терминал; Windows: командная строка или PowerShell) и выполните:

```bash
git clone https://github.com/geocrane/search_agent.git
cd search_agent
```

Папка `search_agent` появится там, где вы находились в терминале. Запомните это место — туда же
будут складываться результаты.

## Шаг 3. Первый запуск

**macOS / Linux**

```bash
./start.sh
```

На macOS можно вместо этого дважды щёлкнуть по файлу `start.command` в папке проекта.

**Windows**

Дважды щёлкните по `start.bat` (или наберите `start.bat` в командной строке).

Первый запуск идёт **5–15 минут** — скачивается браузер Chromium и библиотеки. Скрипт по шагам:

1. находит подходящий Python и создаёт виртуальное окружение `.venv`;
2. ставит зависимости из `requirements.txt` (при следующих запусках — только если файл менялся);
3. докачивает Chromium для `playwright` и `patchright` — один раз;
4. готовит файл `.env` для ключей;
5. поднимает интерфейс на **http://127.0.0.1:8770/** и открывает браузер.

Когда в терминале появится строка «Запускаю интерфейс», браузер откроется сам. Если не открылся —
перейдите по адресу вручную.

**Остановить** — `Ctrl+C` в окне терминала. Окно терминала должно оставаться открытым всё время
работы: это и есть работающий сервер.

**Следующие запуски** — та же команда, но уже за 5–10 секунд.

## Шаг 4. Ввести ключи в интерфейсе

В правом верхнем углу нажмите кнопку **«Модель»**. Откроется окно «Модель и поиск»:

| Поле | Что вписать |
|---|---|
| **Модель** | выберите из списка (по умолчанию GLM — хороший баланс цены и качества) |
| **URL источника** | оставьте как есть |
| **Токен модели** | ключ `FOUNDATION_KEY` из шага 1 |
| **Токен поиска** | ключ Serper из шага 1 |

Нажмите **«Сохранить»**. Ключи запишутся в файл `.env`.

Проверить, что всё живо: кнопка **«⚡ Проверка»** рядом. Она делает один реальный поисковый запрос
и два коротких обращения к модели, показывает скорость ответа и действующие настройки.

## Шаг 5. Подготовить файл с товарами

Подойдёт **.xlsx**, **.xls** или **.csv**. Требование одно: должна быть колонка с наименованиями
товаров. Инструмент сам найдёт строку заголовка и нужную колонку — распознаются названия
**Наименование, Название, Номенклатура, Товар, Позиция, Описание, Модель, Item, Name, Product**
и подобные.

Пример:

| № | Наименование | Кол-во | Ед. изм. |
|---|---|---|---|
| 1 | Кабель ВВГнг(А)-LS 3х2.5 | 500 | м |
| 2 | Автоматический выключатель ABB S203 C16 | 12 | шт |

Чем точнее наименование, тем лучше результат: производитель и артикул в названии сильно
повышают шанс найти именно тот товар.

## Шаг 6. Найти цены

1. **Загрузите файл** — перетащите его в область «Перетащите Excel/CSV» или щёлкните по ней.
   Товары появятся в таблице слева.

2. **Проверьте уточнение к запросу.** Поле «Уточнение к запросу (фраза-суффикс)» добавляется
   к каждому наименованию при поиске. По умолчанию `цена купить`. Полезно вписать регион или
   условие: `купить в Ростове с доставкой`, `оптом цена`.

3. **Галочка «Запросы формирует модель»** (по умолчанию выключена) — если включить, модель
   заранее перепишет наименования в «магазинные» запросы: расшифрует сокращения, уберёт коды
   спецификаций. На технических номенклатурах это заметно улучшает выдачу, но добавляет пакет
   платных обращений к модели до начала поиска и увеличивает время старта.

4. Нажмите **«Найти»**.

Дальше агент идёт по позициям сам. По каждой в таблице видно: статус, найденную цену, для какого
именно товара она названа, диапазон цен по источникам и время. Справа — вкладки:

- **Ход** — подробный журнал: какой запрос ушёл, какой сайт открылся, что заблокировало;
- **Модель** — что именно модель ответила по каждой позиции;
- **Очередь** — что обрабатывается прямо сейчас и что ждёт.

Поиск можно **остановить** («⏹ Стоп») и продолжить позже — прогресс сохраняется. Повторное
нажатие «Найти» продолжает с места обрыва, а не начинает заново.

**Промежуточные результаты пишутся на диск автоматически** каждые 10 закрытых позиций — в папку
`results/` внутри проекта, отдельная подпапка на каждый запуск. Если что-то оборвётся на четвёртом
часу, работа не пропадёт.

## Шаг 7. Забрать отчёт

Кнопка **«📑 Отчёт (xlsx)»** — файл скачивается сразу, модель при этом не вызывается.

В отчёте два листа:

- **Итоги** — Товар, Цена, Тип цены, Найденное название, Мин, Макс, Источник, Ссылка,
  Комментарий модели. Комментарий объясняет, откуда цена, почему выбрана именно она и на что
  обратить внимание (например, что цена указана за упаковку, а не за штуку).
- **Детали** — все сайты из выдачи с ценами, статусами и пояснениями. Нужен, когда итоговая
  цена вызывает вопросы и хочется посмотреть, из чего она сложилась.

## Интерфейс по частям

| Элемент | Что делает |
|---|---|
| **Модель** (вверху справа) | выбор модели и ввод обоих ключей |
| **⚡ Проверка** | проверка поиска и модели с замером скорости |
| **⚙** | настройки: открытие сайтов, очистка страниц, фильтры источников |
| **Найти** | запустить или продолжить поиск |
| **⏹ Стоп** | остановить; прогресс сохраняется |
| **📑 Отчёт (xlsx)** | скачать готовый Excel |
| **Сбросить прогресс** | стереть результаты и начать заново (с подтверждением) |
| Счётчик ₽ вверху | расход на модель: за текущую сессию и накопительно |

В окне **⚙ → «Открытие сайтов и очистка»** настраивается, как упорно обходить антибот-защиты,
какие домены предпочитать (`petrovich.ru, vseinstrumenti.ru`), какие исключать
(`market.yandex.ru, avito.ru`), и когда останавливаться — например, «3 разных магазина — дальше
не искать». Чем раньше останавливаться, тем быстрее и дешевле, но тем уже разброс цен.

## Сколько это стоит и сколько занимает

Ориентиры на позицию:

- **1 поисковый запрос** (иногда 2, если с первой страницы цен не нашлось) из лимита Serper;
- **несколько обращений к модели** — разбор наименования, чтение страниц, комментарий;
- **от 2-3 минут**, в зависимости от того, сколько сайтов пришлось открыть
  и насколько упорно они защищаются.

Текущий расход в рублях виден вверху интерфейса и обновляется по ходу работы. 

## Если что-то пошло не так

**«command not found: python3» / «python не является внутренней командой»**
Python не установлен или не добавлен в PATH. Переустановите с
[python.org](https://www.python.org/downloads/), на Windows отметьте «Add Python to PATH».

**`./start.sh: Permission denied`**
Выполните `chmod +x start.sh` и запустите снова.

**`ModuleNotFoundError: No module named 'uvicorn'` (или `fastapi`, `openai`, `playwright`)**
Окружение неполное, нужно убедиться, что установились все библиотеки.
Крайнее средство — удалить папку `.venv` и запустить стартовый скрипт заново: окружение
соберётся с нуля.

**Браузер не открылся сам**
Откройте http://127.0.0.1:8770/ вручную. 

**«⚠ ключ поиска не задан» или поиск ничего не находит**
Ключ Serper не введён или кончился бесплатный лимит. Заведите новый на serper.dev и вставьте
в окне «Модель» → «Токен поиска» — он подхватится сразу.

**«Модель недоступна» / ошибки авторизации**
Проверьте токен в окне «Модель». Нажмите «⚡ Проверка» — она скажет, отвечает ли модель и с какой
скоростью.

**Цены не находятся у конкретных позиций**
Чаще всего наименование слишком общее либо с ошибкой.
Уточните название, добавьте производителя, поправьте фразу-суффикс под регион.

**Всё работает медленно**
Нажмите «⚡ Проверка» — будут показаны замеры скорости.   
Ускоряет: остановка после 2–3 магазинов (⚙ → «Открытие сайтов»).

**Нужен подробный журнал**
Вкладка «Ход» с уровнем DEBUG, либо файл `runs/logs/webui.log` в папке проекта.

## Настройка

Тонкие параметры лежат в папке `config/` — обычные YAML-файлы с комментариями, править можно
текстовым редактором (после правки перезапустите инструмент):

| Файл | За что отвечает |
|---|---|
| `discovery.yaml` | поиск источников: сколько кандидатов брать, размер пакета разбора, фраза-суффикс по умолчанию |
| `fetch.yaml` | загрузка страниц: режим браузера, антибот, таймауты, параллельность |
| `clean.yaml` | очистка страницы перед отправкой модели |
| `extract.yaml` | извлечение цен: параллельность, пределы ожидания |
| `adjudicate.yaml` | отбор итоговой цены: отсев приманок и выбросов |
| `report.yaml` | отчёт: комментарии модели, частота промежуточных сохранений |
| `llm.yaml` | лимиты обращений к модели (запросов в секунду/минуту, поведение при перегрузке) |
| `models.yaml` | каталог доступных моделей с ценами |
| `sources.yaml` | рейтинг источников по тирам, чёрный список |

Ключи и адрес API хранятся в файле `.env` в корне проекта — он создаётся при первом запуске
и в репозиторий не попадает.

Рабочее состояние (кэш загруженных страниц, профиль браузера, логи, история прогонов) лежит
в `runs/`, результаты — в `results/`. Обе папки можно удалять: кэш пересоберётся, история
прогонов при этом потеряется.


## Устройство проекта

| Каталог | Содержимое |
|---|---|
| `search_agent/` | движок: обнаружение источников, загрузка и антибот, извлечение цен, свод, отчёт |
| `webui/` | локальный интерфейс: FastAPI + статика, живые события по WebSocket |
| `config/` | настройки в YAML (см. выше) |
| `scripts/` | подготовка `.env` при запуске |
| `runs/` | рабочее состояние: кэш страниц, профиль браузера, логи, история (создаётся сам) |
| `results/` | промежуточные и итоговые файлы прогонов (создаётся сам) |

Поиск источников идёт через Serper (выдача Google), модель вызывается напрямую по HTTP API
Foundation Models.
